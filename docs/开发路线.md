# 开发路线

## 总体原则

- 每个阶段结束时项目都可以构建和启动。
- 每个阶段先完成数据库迁移和领域测试，再接 HTTP 或前端。
- 不一次性写完所有模块后集中排查。
- 涉及外部 DNS、TLS 和对象存储的能力必须提供本地替代实现。
- 没有真实测试数据的功能不进入“已完成”状态。

## 当前技术债

- 原项目只有一次初始提交，已有实现与目标架构差距较大。
- 原协程池存在队列满静默丢任务问题。
- 原限流键和 Lua TTL 参数存在错误。
- 原点击统计只在缓存未命中时执行。
- `cmd/server/planb1.go` 是与短链无关的未跟踪临时文件，会和服务入口冲突。
