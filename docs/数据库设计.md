# 数据库设计

本文包含当前已落地表和后续目标表。当前迁移只创建以下表：

- `users`
- `workspaces`
- `workspace_members`
- `refresh_tokens`
- `domains`
- `links`
- `click_events`
- `idempotency_keys`
- `trial_sessions`
- `api_keys`
- `webhook_endpoints`
- `webhook_deliveries`
- `blocked_domains`
- `abuse_reports`
- `audit_logs`

`workspaces.kind` 区分正式空间和游客空间。正式空间的 `owner_user_id` 必填；
游客空间 `kind=2` 且不绑定登录用户。

后文出现的文件夹、标签、二维码资源、批量任务和预聚合表
属于目标设计，尚无可执行迁移，不能按“现有表”使用。

## 1. 当前数据职责

MySQL：

- 用户、工作空间、认证。
- 链接元数据。
- 域名和验证状态。
- 点击事件明细。
- 创建短链幂等状态。
- 滥用举报、目标域名黑名单和管理员审计。
- 游客 Cookie Token 哈希、链接配额和会话过期时间。

Redis：

- 跳转缓存。
- 滑动窗口限流状态。
- Redis Streams 点击事件。

## 2. 标识策略

业务实体使用 26 位 ULID：

- 按时间大致有序。
- 可以安全作为 API ID 暴露。
- 不依赖数据库自增，方便后续扩容。
- 字符集固定为 ASCII。

数据库字段：

```sql
id CHAR(26) CHARACTER SET ascii COLLATE ascii_bin NOT NULL
```

短码与实体 ID 分离。短码使用安全随机 Base62，允许用户自定义别名。

## 4. MySQL 分析表

当前迁移只创建 `click_events`，分析接口直接查询明细。下面的时间与维度汇总表
是已验证过执行计划的后续优化方案，当前不建表，避免在数据量尚未证明需要时
增加写入复杂度。

### 4.1 `click_events`

```sql
CREATE TABLE click_events (
    event_id CHAR(26) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
    workspace_id CHAR(26) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
    link_id CHAR(26) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
    qr_id CHAR(26) CHARACTER SET ascii COLLATE ascii_bin NULL,
    domain_id CHAR(26) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
    slug VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
    clicked_at DATETIME(3) NOT NULL,
    visitor_hash BINARY(32) NOT NULL,
    country CHAR(2) CHARACTER SET ascii NOT NULL DEFAULT '',
    region VARCHAR(64) NOT NULL DEFAULT '',
    city VARCHAR(64) NOT NULL DEFAULT '',
    device VARCHAR(16) NOT NULL DEFAULT '',
    os VARCHAR(32) NOT NULL DEFAULT '',
    browser VARCHAR(32) NOT NULL DEFAULT '',
    language VARCHAR(16) NOT NULL DEFAULT '',
    referrer VARCHAR(2048) NOT NULL DEFAULT '',
    utm_source VARCHAR(255) NOT NULL DEFAULT '',
    utm_medium VARCHAR(255) NOT NULL DEFAULT '',
    utm_campaign VARCHAR(255) NOT NULL DEFAULT '',
    utm_term VARCHAR(255) NOT NULL DEFAULT '',
    utm_content VARCHAR(255) NOT NULL DEFAULT '',
    is_bot TINYINT(1) NOT NULL DEFAULT 0,
    route_variant VARCHAR(32) NOT NULL DEFAULT '',
    created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    PRIMARY KEY (event_id),
    KEY idx_click_events_link_time (workspace_id, link_id, clicked_at),
    KEY idx_click_events_workspace_time (workspace_id, clicked_at),
    KEY idx_click_events_qr_time (workspace_id, qr_id, clicked_at),
    KEY idx_click_events_retention (clicked_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

`event_id` 由 API 在写入 Stream 前生成，直接作为主键和消费幂等键。`workspace_id`、`link_id` 和 `slug` 是分析所需的稳定快照，链接后续改名或删除不会破坏历史统计。

### 4.2 `link_time_stats`

```sql
CREATE TABLE link_time_stats (
    workspace_id CHAR(26) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
    link_id CHAR(26) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
    bucket_seconds INT UNSIGNED NOT NULL,
    bucket_start DATETIME NOT NULL,
    human_clicks BIGINT UNSIGNED NOT NULL DEFAULT 0,
    bot_clicks BIGINT UNSIGNED NOT NULL DEFAULT 0,
    unique_visitors BIGINT UNSIGNED NOT NULL DEFAULT 0,
    updated_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
        ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (workspace_id, link_id, bucket_seconds, bucket_start),
    KEY idx_link_time_workspace_bucket (
        workspace_id,
        bucket_seconds,
        bucket_start,
        link_id
    )
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

`bucket_seconds` 的有效值：

- `3600`：小时趋势，保存最近 90 天。
- `86400`：每日趋势，用于长周期查询。

`unique_visitors` 是当前时间桶内使用 Redis HyperLogLog 得到的近似值，不能把多个桶的值相加作为更长周期的独立访客总数。

```sql
    unique_visitors BIGINT UNSIGNED NOT NULL DEFAULT 0,
    updated_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
        ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (
        workspace_id,
        link_id,
        stat_date,
        dimension_type,
        dimension_value
    ),
    KEY idx_link_dimension_workspace (

    )
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

`dimension_type` 的有效值：

- `country`：国家或地区。
- `device`：mobile、desktop、tablet。
- `os`：操作系统。
- `browser`：浏览器。
- `language`：访客语言。
- `referrer`：来源域名。
- `utm_source`：活动来源。
- `utm_medium`：活动媒介。
- `utm_campaign`：活动名称。
- `qr`：二维码来源。

### 4.6 写入与查询约束

- Worker 使用 `INSERT IGNORE` 批量写入点击明细，依靠 `event_id` 主键处理重复消费。
- 明细写入成功后，汇总任务按受影响的链接和时间桶执行集合查询。
- 汇总使用 `INSERT ... SELECT ... ON DUPLICATE KEY UPDATE` 覆盖当前桶的绝对计数，不使用 `clicks = clicks + 1` 累加。
- 同一批次或范围重复执行得到相同绝对结果，因此消费者重试不会造成重复统计。
- 最近时间桶允许重复重算，以吸收延迟到达的点击；历史桶只执行一次并记录完成状态。
- 所有查询必须带 `workspace_id`，防止跨工作空间读取。
- 24 小时和 7 天趋势读取 `bucket_seconds=3600`，30 天以上趋势读取 `bucket_seconds=86400`。
- 工作空间仪表盘读取 `workspace_time_stats` 和 `workspace_dimension_daily_stats`。
- 单链接详情读取 `link_time_stats` 和 `link_dimension_daily_stats`。
- 原始点击明细按保留策略定期清理，不参与长期趋势查询。
