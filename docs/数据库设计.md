# 数据库设计

## 1. 数据职责

MySQL：

- 用户、工作空间、认证。
- 链接元数据。
- 域名和验证状态。
- 二维码配置。
- 文件夹、标签。
- API Key、Webhook、批量任务和审计日志。

ClickHouse：

- 点击事件明细。
- 时间、地域、设备和来源等多维分析。

Redis：

- 跳转缓存。
- 限流计数。
- 验证码或短期密码凭证。
- 独立访客 HyperLogLog。
- Redis Streams 点击事件。

## 2. 标识策略

业务实体使用 26 位 ULID：

- 按时间大致有序。
- 可以安全作为 API ID 暴露。
- 不依赖数据库自增，方便后续扩容。
- 字符集固定为 ASCII。

数据库字段：

```sql
id CHAR(26) CHARACTER SET ascii COLLATE ascii_bin NOT NULL
```

短码与实体 ID 分离。短码使用安全随机 Base62，允许用户自定义别名。

## 4. ClickHouse

### 4.1 `click_events`

```sql
CREATE TABLE click_events
(
    event_id UUID,
    workspace_id String,
    link_id String,
    qr_id Nullable(String),
    domain_id String,
    slug String,
    clicked_at DateTime64(3, 'UTC'),
    visitor_hash FixedString(32),
    country LowCardinality(String),
    region LowCardinality(String),
    city LowCardinality(String),
    device LowCardinality(String),
    os LowCardinality(String),
    browser LowCardinality(String),
    language LowCardinality(String),
    referrer String,
    utm_source LowCardinality(String),
    utm_medium LowCardinality(String),
    utm_campaign LowCardinality(String),
    utm_term LowCardinality(String),
    utm_content LowCardinality(String),
    is_bot UInt8,
    route_variant LowCardinality(String)
)
ENGINE = MergeTree
PARTITION BY toYYYYMM(clicked_at)
ORDER BY (workspace_id, link_id, clicked_at, event_id)
TTL clicked_at + INTERVAL 2 YEAR;
```

查询约定：

- 总点击使用 `uniqExact(event_id)`，容忍 Stream 重复投递。
- 独立访客使用 `uniqExact(visitor_hash)`。
- 机器人通过 `is_bot` 单独过滤。
- 所有查询必须带工作空间条件。
- 长周期查询按小时或日期聚合。

## 5. Redis Key

```text
link:v1:{domain_id}:{slug}
null:v1:{domain_id}:{slug}
idem:v1:{workspace_id}:{key}
limit:ip:{route}:{ip_hash}
limit:user:{route}:{user_id}
uv:{workspace_id}:{link_id}:{date}
shorturl:clicks
domain:hostname:{hostname}
tls:authorized:{hostname}
```

所有 Key 必须设置 TTL，Stream 使用保留策略和监控，不使用无限增长配置。
