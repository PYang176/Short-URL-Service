# 接口设计

## 1. 通用约定

Base URL：

```text
/api/v1
```

认证：

```http
Authorization: Bearer <access_token>
```

每个响应包含：

```http
X-Request-ID: <request-id>
```

错误响应：

```json
{
  "error": {
    "code": "INVALID_REQUEST",
    "message": "human readable message",
    "request_id": "..."
  }
}
```

时间统一使用 RFC 3339 UTC 格式。

## 2. 已实现接口

### 注册

```http
POST /api/v1/auth/register
```

请求：

```json
{
  "email": "user@example.com",
  "password": "password123",
  "display_name": "User"
}
```

响应：`201 Created`

```json
{
  "user": {
    "id": "01...",
    "email": "user@example.com",
    "display_name": "User",
    "role": 1,
    "created_at": "2026-11-12T10:00:00Z"
  },
  "workspace": {
    "id": "01...",
    "name": "User 的空间",
    "slug": "ws_01...",
    "created_at": "2026-11-12T10:00:00Z"
  },
  "token": {
    "access_token": "<jwt>",
    "token_type": "Bearer",
    "expires_at": "2026-11-12T10:15:00Z",
    "refresh_token": "srt_..."
  }
}
```

错误：

| HTTP | Code | 场景 |
| --- | --- | --- |
| 400 | `INVALID_INPUT` | 邮箱、密码或名称不合法 |
| 409 | `EMAIL_EXISTS` | 邮箱已注册 |

### 登录

```http
POST /api/v1/auth/login
```

请求：

```json
{
  "email": "user@example.com",
  "password": "password123"
}
```

响应：`200 OK`，结构与注册相同。

### 刷新令牌

```http
POST /api/v1/auth/refresh
```

请求：

```json
{
  "refresh_token": "srt_..."
}
```

响应：`200 OK`，返回新的 Access Token 和 Refresh Token。

旧 Refresh Token 再次使用返回：

```json
{
  "error": {
    "code": "REFRESH_TOKEN_REUSED",
    "message": "refresh token has already been used",
    "request_id": "..."
  }
}
```

### 退出

```http
POST /api/v1/auth/logout
```

请求：

```json
{
  "refresh_token": "srt_..."
}
```

响应：`204 No Content`。

### 当前用户

```http
GET /api/v1/me
Authorization: Bearer <access_token>
```

响应：

```json
{
  "user": {},
  "workspace": {}
}
```

### 修改资料

```http
PATCH /api/v1/me
Authorization: Bearer <access_token>
```

请求：

```json
{
  "display_name": "New name"
}
```

响应：`200 OK`。

## 3. 已实现短链接接口

### 创建短链

```http
POST /api/v1/links
Authorization: Bearer <access_token>
```

请求：

```json
{
  "destination_url": "https://example.com/landing",
  "alias": "launch",
  "title": "Launch page",
  "notes": "",
  "redirect_code": 302,
  "starts_at": null,
  "expires_at": null
}
```

响应：`201 Created`

```json
{
  "id": "01...",
  "slug": "launch",
  "short_url": "http://localhost:18080/r/launch",
  "destination_url": "https://example.com/landing",
  "title": "Launch page",
  "notes": "",
  "status": 1,
  "redirect_code": 302,
  "starts_at": null,
  "expires_at": null,
  "created_at": "2026-11-12T10:00:00Z"
}
```

错误：

| HTTP | Code | 场景 |
| --- | --- | --- |
| 400 | `INVALID_INPUT` | URL、短码或时间范围不合法 |
| 409 | `SLUG_TAKEN` | 自定义短码已被占用 |

### 链接列表

```http
GET /api/v1/links?limit=20&cursor=<opaque-cursor>
Authorization: Bearer <access_token>
```

响应：

```json
{
  "items": [],
  "next_cursor": ""
}
```

### 链接详情、修改和删除

```text
GET    /api/v1/links/{id}
PATCH  /api/v1/links/{id}
DELETE /api/v1/links/{id}
```

### 二维码

```http
GET /api/v1/links/{id}/qr?format=png&size=512
Authorization: Bearer <access_token>
```

- `format` 支持 `png`、`svg`。
- `size` 有效范围为 128 至 1024。
- 二维码编码完整短链地址并附带 `utm_source=qr`。
- 修改目标地址后二维码内容不变，仍然可以正常跳转。

修改请求的字段均可选：

```json
{
  "destination_url": "https://example.com/new-page",
  "title": "New title",
  "notes": "new notes",
  "status": 1,
  "redirect_code": 301,
  "expires_at": "2026-12-31T23:59:59Z",
  "clear_expires_at": false
}
```

### 公开跳转

```http
GET /r/{slug}
```

有效链接返回 `301` 或 `302`。不存在、已删除或尚未生效返回 `404`，
停用或过期返回 `410`。已删除资源统一返回 `404`，避免向外暴露删除历史。

### 点击分析

```http
GET /api/v1/links/{id}/analytics?days=30
Authorization: Bearer <access_token>
```

`days` 有效范围为 1 至 90。响应包含：

- 总点击、人类点击、机器人点击和独立访客。
- 按小时或按天的点击趋势。
- 国家、设备、操作系统、浏览器和来源排行。

点击事件通过 Redis Streams 异步写入 MySQL，接口允许短暂最终一致。
