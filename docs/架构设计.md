# 短链接平台架构设计

本文描述当前代码基线和后续目标架构。已实现范围以 README、路由和数据库
迁移为准；标为“规划”的模块尚未进入当前运行链路，不能作为已交付能力。

## 1. 架构结论

系统采用模块化单体，同一个代码仓库提供两个运行角色：

```text
cmd/api       HTTP API、管理接口、公开跳转
cmd/worker    Redis Streams 点击消费、Webhook 投递、过期游客数据清理
```

普通用户只访问短链、二维码和访问分析。平台管理员角色由 Access Token 携带，
域名、API Key 和 Webhook 管理路由在中间件层校验管理员角色。

不拆分微服务。API 和 Worker 共享领域代码，但可以独立扩容、独立发布和独立监控。
MySQL 使用宿主机本地实例，不放入 Docker；Docker Compose 只运行 Redis、
API、Worker、Nginx 和一次性迁移任务。

API、Worker 和迁移任务共用一个 `shorturl-app:local` 镜像，其中包含
`/app/api`、`/app/worker` 和 `/app/migrate`。Compose 通过不同 `command`
形成独立服务，从而保留独立扩缩容、日志和故障域，同时避免维护三个内容相同
的应用镜像标签。Web 使用独立 Nginx 镜像。

## 4. 业务模块

```text
internal
├── app          应用装配与生命周期
├── identity     注册、登录、Token、工作空间
├── link         链接管理、跳转决策、缓存
├── domain       域名验证和 Host 路由
├── analytics    点击事件、消费和查询
├── trial        游客会话、配额和临时链接
├── webhook      Webhook 配置、Outbox 投递和签名
├── abuse        公开举报、域名黑名单和审计日志
├── platform     配置、数据库、Redis、限流、幂等和指标
└── transport    HTTP 中间件与响应
```

模块内部采用：

```text
handler -> service -> repository
```

跨模块依赖通过小型接口和明确的应用服务完成，不允许 Handler 直接访问其他模块 Repository。

文件夹、标签、批量任务、管理治理和分享报表仍在规划中，
当前代码没有对应模块或迁移。目标模型见数据库设计和需求规格。

## 5. 链接跳转链路

```text
HTTP 请求
  -> 解析 Host，确定域名
  -> 路径提取短码
  -> Redis 读取链接缓存
      -> 命中：检查状态和生效时间
      -> 未命中：singleflight 合并回源
          -> MySQL 查询
          -> 写入缓存
  -> 返回 301/302 或错误页面
  -> XADD 点击事件
```

缓存值包含：

```json
{
  "id": "...",
  "workspace_id": "...",
  "destination_url": "https://example.com",
  "status": 1,
  "redirect_code": 302,
  "starts_at": null,
  "expires_at": null,
  "version": 1
}
```

缓存 Key：

```text
link:v1:{domain_id}:{slug}
```

缓存策略：

- 未找到使用短 TTL 空值缓存。
- 普通缓存 TTL 为 30 分钟加随机抖动。
- 如果链接将在更短时间内过期，TTL 不超过剩余时间。
- 更新和删除完成后删除缓存。
- Redis 错误时记录指标并回源 MySQL。
- 跳转不依赖点击事件是否成功写入。

## 6. 点击分析链路

```text
cmd/api
  -> XADD shorturl:clicks

cmd/worker
  -> XREADGROUP
  -> 解析 User-Agent、CF-IPCountry、Accept-Language、Referer 和 UTM
  -> 批量写入 MySQL 点击明细
  -> XACK
  -> 定时 XAUTOCLAIM 处理超时 Pending
```

事件字段不使用原始 IP。访客哈希：

```text
visitor_hash = HMAC-SHA256(ANALYTICS_HASH_SECRET, YYYY-MM-DD | ip | user_agent)
```

当前实现把日期、原始 IP 和 User-Agent 依次写入同一个 HMAC 输入，不保存原始
IP，也不调用外部 IP 地理定位服务。国家代码读取 `CF-IPCountry` Header；
部署时必须由可信边缘代理覆盖该 Header，直接暴露 API 时该字段仅用于非关键
分析，不能作为安全判断依据。

一致性语义：

- Stream 写入成功后至少一次消费。
- MySQL 使用事件 ID 唯一约束保证重复消费幂等。
- 重复消费不得重复计算唯一访客。
- 统计允许 10 秒最终一致。
- Stream 写入失败不回滚跳转。
- 当前直接查询点击明细；只有实测出现性能问题后才增加汇总表。

工作空间总览直接使用 `click_events(workspace_id, clicked_at)` 和链接工作空间索引：

```text
链接总量/有效启用量
  -> links(workspace_id, deleted_at/status/时间窗口)

点击总量、访客、趋势
  -> click_events(workspace_id, clicked_at)

Top 5 链接
  -> links LEFT JOIN click_events
```

总览接口从登录 Token 获取工作空间，不接收客户端 workspace ID。

## 7. 自定义域名

域名状态机：

```text
pending
  -> verifying
      -> verified
      -> failed

verified
  -> disabled
  -> deleted
```

验证接口：

```go
type Resolver interface {
    LookupTXT(ctx context.Context, name string) ([]string, error)
    LookupCNAME(ctx context.Context, host string) (string, error)
}
```

当前实现：

- `DNSResolver`：查询 TXT 和 CNAME 记录。
- `FakeResolver`：开发与自动化测试。
- 当前由用户触发验证接口：`mock` 直接成功，`dns` 同步查询 TXT 和 CNAME。
- 自动轮询验证暂未实现，避免在没有真实 DNS 环境时增加后台任务复杂度。

生产 HTTPS 尚未接入。目标设计：

- 反向代理按已验证域名签发证书。
- Caddy 在签发证书前调用内部授权接口。
- 授权接口只允许已验证并归属于当前工作空间的域名。
- 开发环境使用 Caddy 内部 CA 和本地 Host。

本地模拟方式：

```text
DOMAIN_VERIFY_MODE=mock
DEV_CUSTOM_DOMAIN=go.local.test
127.0.0.1 go.local.test
```

模拟验证接口在 `APP_ENV=production` 时不会注册。

## 8. 二维码

二维码编码稳定的短链 URL，而不是目标 URL：

```text
QR payload: https://go.local.test/promo
link destination: https://example.com/campaign
```

二维码配置与渲染分离：

当前实现由服务端按请求生成 PNG/SVG，二维码内容指向稳定短链。二维码配置
持久化、样式编辑、Logo 和对象存储尚未实现；这些属于后续资源管理能力。

### 8.1 匿名试用

```text
POST /api/v1/trial/links
  -> 读取或创建 HttpOnly 游客 Cookie
  -> 查询 trial_sessions
  -> 原子占用一条游客链接配额
  -> 创建 kind=2 游客工作空间下的默认域名短链
  -> 链接过期时间与会话结束时间一致

POST /api/v1/trial/claim
  -> 校验登录工作空间和游客 Cookie
  -> 锁定 trial_session 与目标工作空间
  -> 迁移 links 和 click_events 的 workspace_id
  -> 清除临时 expires_at
  -> 删除游客会话和游客工作空间
  -> 失效旧跳转缓存
```

数据库只保存 Cookie Token 的 SHA-256 摘要。Worker 定期删除过期游客会话、
链接和点击明细。游客不能添加自定义域名，也不能访问正式工作空间接口。
Worker 写入点击前会按链接当前归属校正 workspace，处理认领前已经进入 Stream
但尚未消费的点击。

## 9. API Key 与 Webhook

API Key 和 Webhook 均已实现。

API Key、Webhook 和域名管理属于平台管理员能力。普通用户即使绕过前端直接
请求接口，也会在 `RequirePlatformAdmin` 中间件收到 403。

API Key：

- 格式为 `sl_live_<prefix>.<secret>`。
- 数据库保存前缀和完整 Key 的 SHA-256 摘要。
- 明文只在创建时返回一次。
- 认证时按前缀查候选，再使用常量时间比较。
- 支持 `links:read`、`links:write`、`analytics:read` 作用域。
- 短链和分析资源路由同时接受 JWT 与 API Key，API Key 按 Key+IP 限流。

Webhook：

- Webhook 管理接口只接受 JWT，不允许 API Key 修改回调配置。
- 链接创建、修改或删除时，业务写入与 Outbox 任务在同一个 MySQL 事务中提交。
- 事件类型包括 `link.created`、`link.updated` 和 `link.deleted`。
- Worker 使用 `FOR UPDATE SKIP LOCKED` 领取任务，多个 Worker 不会重复锁定同一条记录。
- 请求使用 `X-ShortURL-Event-ID`、`X-ShortURL-Event-Type`、
  `X-ShortURL-Timestamp` 和 `X-ShortURL-Signature`。
- 签名算法为 HMAC-SHA256，原文是 `timestamp + "." + body`，签名值带
  `sha256=` 前缀。
- 只有 2xx 算成功；非 2xx、超时、连接失败和重定向都进入重试。
- 失败使用有上限的指数退避；达到最大次数后终止任务并自动停用端点。
- Secret 使用 AES-GCM 加密保存，只在创建响应中返回一次。
- 公网模式只允许 HTTPS，并在解析和连接阶段阻止回环、私网和链路本地地址。
- 本地演示通过 `WEBHOOK_ALLOW_PRIVATE_TARGETS=true` 允许私网 HTTP 目标。

滥用治理：

- 公开举报使用独立 IP 限流，不要求登录。
- 管理员举报队列、裁决和黑名单接口复用平台管理员权限。
- 举报处理事务同时更新举报、短链状态和审计日志。
- 下架提交后由链接服务删除 Redis 缓存，避免已下架短链继续命中旧快照。
- 目标域名黑名单在创建和修改链接时检查，支持精确域名、子域名和 IP。

## 11. 生命周期

API：

- 启动时初始化配置、日志、MySQL、Redis、路由和指标。
- 收到 SIGINT/SIGTERM 后停止接收新请求。
- 在超时时间内完成在途请求。
- 关闭数据库连接。

Worker：

- 启动 Consumer Group 和周期任务。
- 退出时停止领取新任务。
- 当前批次提交或安全回到 Pending 后再退出。

迁移任务：

- 每次部署执行一次 `migrate up`，完成后退出。
- Goose 使用版本表跳过已应用迁移，重复运行不会再次执行 Up SQL。
- API 和 Worker 等待迁移任务成功后再启动。
- 生产环境 `migrate down` 需要显式设置 `ALLOW_MIGRATION_DOWN=true`。
